# 长途分段观测修复与实机验证

## 原因与修正

travel.plan_leg优先尝试完整远端目标，radius原只约束候选端点，并未截短成功的完整路线。一腿可能数百码。backend._send_path虽按30码分RPC，却整个路线完成前不drain，长时间无人消费1024包桥接队列；vendor_return_o出现capture gap与此明确代码空窗相符。尚无逐RPC时间剖析证明每次历史溢出都同因。

修正：每成功发送一个路径分块后drain；规划输出沿原导航折线按radius的3D长度截短，计入起点到首点距离，不走直线捷径，不放大队列。导航单次同步查询仍可能阻塞约10秒、多候选间仍需进一步评估；本次没有声称消除所有观测空窗。

3项新回归测试覆盖截断包含首段、坡度/转折长度、真实_send_path逐块send/drain交替。WSL全量470项通过。
