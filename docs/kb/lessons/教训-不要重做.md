# 教训 · 不要重做（已否决的方案清单）

> 每一行都是**真金白银换来的**（多数一次角色死亡）。
> 动手前先在这里搜一遍。

## 工程做法

| 别做 | 原因 | 出处 |
|---|---|---|
| **另写一套平行实现**，而不先找既有模块 | `agent_wow_recovery_plan.py`/`recovery_control.py` 早已实现跑尸，且**几何更优**；我另写了一套更差的，还贴错"首次实机验证"标签 | docs/119 |
| **按自己新起的文件名搜既有实现** | 搜 `recovery\|corpse` 才命中；按 `my_corpse_run` 搜会搜空 | docs/119 |
| **报告字段"看起来正常"就当验证通过** | esc008 的 `requests`/`retreat_outcome` 全"正常"，实为**击杀**。判据必须独立于实现（改成看**目标实时 HP**） | docs/118 |
| **把"观察"当被动** | "被动观察"阶段**没停自身攻击** → 角色在"观察"期间把怪打死了 | esc008 |
| **用登录点当"当前位置"** | 服务端**不回广播自身位置**，登录点在整场会话里都是过期的；权威位置是桥接返回的 `submittedPosition` | esc010/013/014/022 |
| **用 `select_target` 存的旧目标算位置** | 世界状态**每次更新都替换对象**，旧对象的外推路径会跳 → 同一瞬间两次测量差 **8.4 码** | b8_u1 |
| **在 PowerShell 用 `Set-Content -Encoding UTF8` 改代码** | 会写 **BOM**，之后 `ast.parse` 直接报错 | 多次 |
| **实机前不先做离线测量** | 抓包逐包统计几分钟就能答一个实机要拿命换的问题（位置新鲜度、leash 判定） | 本轮多次 |

## 机制层面

| 别做 | 原因 | 出处 |
|---|---|---|
| **"拉怪"**（仇恨范围内先发 `start_attack` 把怪拉过来） | 破坏 3 项既有契约测试；实机**更危险**（怪会跟着走 → 撤离失效 → 死亡） | b5_u1 |
| **反向接近路线当撤离路线** | 只有 6 码，撤不出仇恨范围 | esc010 |
| **降低低血阈值** | 阈值是"低于它就退出"，**调低 = 退得更晚 = 多挨打**，方向反了 | 阈值讨论 |
| **走向出生点当接近目标** | 出生点可能离怪 15 码，仍进不了近战 | spawn 漂移实测 |
| **用灵魂医者冒充跑尸验证** | 项目纪律明令：灵魂医者是独立恢复手段 | AGENTS.md |

## 结论

**这些是"方向性"的错误，不是"参数没调好"。**
遇到"同一件事反复失败"时，先怀疑方向：去 [[sources]] 的**本机源码**查判定，
而不是再试一轮参数。
