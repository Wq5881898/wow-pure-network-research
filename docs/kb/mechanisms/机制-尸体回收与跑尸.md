# 机制 · 尸体回收与跑尸

| 事实 | 出处 | 值 |
|---|---|---|
| 尸体回收半径 | `src/server/game/Entities/Corpse/Corpse.h`：`CORPSE_RECLAIM_RADIUS` | **39 码** |
| 回收请求 | `CMSG_RECLAIM_CORPSE`（桥接 `bridge.reclaim_corpse`，opcode 0x1D2） | 需要**非活人、已是幽灵、有自身尸体、等待时间结束、同地图、在回收半径内** |
| 复活生命 | 同上 | **50%** |
| 尸体查询 | `CMSG_CORPSE_QUERY`（桥接 `bridge.query_corpse`，opcode 0x216） | 回复含 **found / map / position_xyz / corpse_map** |
| 释放灵魂 | `CMSG_RELEASE_SPIRIT`（桥接 `bridge.release_spirit`，opcode 0x15A） | 角色死后**必须先释放**才会成为幽灵；否则查尸体无回应 |
| 灵魂医者 | `CMSG_SPIRIT_HEALER_ACTIVATE`（opcode 0x21C） | 墓地 NPC，50% 生命复活，有耐久代价 |

## ✅ 连续死亡的"可行路径距离递减"核对（2026-11-01 实机）

AGENTS.md 要求："再死时查询新尸体，以可行路径距离核对是否更接近墓地。"
**这个核对现在有工具了**：`scripts/check_corpse_progress.py`
（读 `results/pure_network/agent_wow_danger_recovery_*.json` 里的
`plan.corpse_to_graveyard_path_length` / `plan.path_progress_before_revive`）。

**实机结果**（`python scripts/check_corpse_progress.py`）：

| 死亡 | 尸体→墓地**可行路径** | 复活前推进 | 说明 |
|---|---|---|---|
| dr02 / dr03 | 88.5 码 | 29.7 码 | 墓地附近的危险区 |
| recov_b37 | 507.9 码 | 32.4 码 | 换到 Felstalker 区狩猎 ⇒ 变远是**预期的** |
| recov_b39 | **392.4 码** | 29.8 码 | 同一狩猎区的下一次死亡 ⇒ **近了 115.5 码** ✓ |

**⇒ 关键结论**
- 比较必须用**可行路径长度**，不能用直线距离；
- "变远"本身不是失败（换区狩猎就会变远），**要看同一区域的下一次死亡是否更近** ✓
  （recov_b37 → recov_b39 正是如此 ✓）；
- 每次恢复都把角色往墓地推进约 **30 码**（`path_progress_before_revive`）——
  这就是"复活后立即跑动"这条纪律的量化证据 ✓

## 关键点

- **尸体对象沿用角色自身 guid**（ObjectTypeId Corpse）→ 靠 guid 识别，不靠猜。
- **`movement.position_xyzo` 是静态的**（出生点），实时位置在 `server_motion` 里外推；
  **前者可靠、后者会跳**。
- **不站到尸体正上方**：39 码半径内即可回收。既有设计
  （`agent_wow_recovery_plan.select_recovery`）选的是**朝墓地推进的连续前缀内的点**。

## 跑尸纪律（AGENTS.md）

- 灵魂医者是**独立恢复手段**，**不能冒充跑尸验证**。
- 复活后**立即跑动**，沿可达路径，不硬走直线。
- 再死时查询新尸体，比对**可行路径距离**是否更接近墓地。
