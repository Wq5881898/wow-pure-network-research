# 机制 · 脱战确认规则（唯一的"战斗结束了"判据）

> **2026-11-06 建立 ✓。** 之前"战斗是否结束"在两处各写了一遍，
> 且退出分支那一份把**未知**当成了**已结束** —— 本条目是两份共用的唯一实现。

## 规则（`agent_wow_combat_state_machine.OutOfCombatConfirmator` ✓）

**"服务器说角色不在战斗了"必须满足三条，缺一不可 ✓**：

1. **不是一次采样就算** ✓ —— 需要 **连续 3 次**确认（`out_of_combat_confirmations` ✓）；
2. **必须覆盖一段驻留时间** ✓ —— 连续段跨度 **≥ 2.0 秒**（`min_disengage_seconds` ✓）；
3. **中间不能有"不确定"的采样** ✓ —— 下面这些都会**打断连续段**：

| 采样 | 后果 |
|---|---|
| `in_combat is None`（**未知**） | 打断连续段，**且永远不计入** ✓ |
| 生命**未下发**（`health_transmitted` 为假 / `health is None`） | 打断连续段，**且永远不计入** ✓ |
| 生命 **= 0**（下发了的零） | 打断连续段（这是死亡）✓ |
| 生命**下降** | 打断连续段（窗口期内还在挨打 ⇒ 窗口无效）✓ |

**⇒ ⇒ 一句话 ✓**：**"一次 False"不等于"已脱战" ✓；"None"永远不等于"已脱战" ✓。**

## 为什么要统一（这是本轮修掉的真缺口）

| 位置 | 原来的写法 | 后果 |
|---|---|---|
| `agent_wow_combat_state_machine.py` | 3 次确认 + 2 秒驻留 ✓ | 正确 ✓ |
| `agent_wow_exit_recovery.py` | **`observation.in_combat is not True`** ✗ | **`None`（未知）被当成"已脱战" ⇒ 报告成成功 ✓** |
| `agent_wow_exit_recovery.py::close_session` | **`observation.in_combat is True` 才拦登出** ✗ | **未知 ⇒ 直接登出并拆除会话 ✓** |
| `agent_wow_escape_control.py::retreat` | **`me['in_combat'] is False`** ✗ | **第一个 False 就结束等待 ✓**（单次采样）✓ |

**⇒ 三处现在共用同一个确认器 ✓**：
- 状态机：`CombatStateMachine._confirmator` ✓；
- 退出分支：`resolve_combat_before_exit` 里的 `confirmator` ✓；
- 撤离等待：`agent_wow_escape_control.retreat` 里的 `confirmator` ✓
  —— **撤离过程自己采到的样本被回灌给退出分支 ✓**（不再重复采样 ✓）。

**⇒ ⇒ 行为上的一个重要区别 ✓**：

- **报告成功** ⇒ 需要确认（3 次 + 2 秒）✓；
- **停止行动** ⇒ **不需要等确认** ✓ —— 服务器一说 `in_combat is False`，
  退出分支就**不再开新战**（开战是副作用，不能等）✓；
  ⇒ **"不要动手"与"可以宣布成功"是两件事 ✓**，本次修复把两者分开了 ✓。
