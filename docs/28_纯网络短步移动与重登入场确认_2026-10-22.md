# 纯网络短步移动与重登入场确认

## 实测结论

Netprobe（GUID 9）通过正式 Docker/gRPC 模块发送一次 0.5 码前向小步并停止，正常退出后重新入场，服务器返回位置与提交终点一致。没有使用 GM 移动、数据库写入或图形客户端输入。

| 坐标 | run03 移动前 | run04 重新入场 | 差值 |
|---|---:|---:|---:|
| X | -618.5180053710938 | -618.0180053710938 | +0.5 |
| Y | -4251.669921875 | -4251.669921875 | 0 |
| Z | 38.71799850463867 | 38.71799850463867 | 0 |
| 朝向 | 0 | 0 | 0 |

两次会话均正常退出 0；移动接口的响应只标注 submittedPosition，真实效果由第二次 LOGIN_VERIFY_WORLD 独立确认。该证据证明服务端接受并保存位置，不证明图形客户端动画、完整地面碰撞或物理模拟等价。

## 协议与实现

- `MSG_MOVE_START_FORWARD=0x0B5`，`MSG_MOVE_STOP=0x0B7`。
- payload：packed mover GUID、uint32 movement flags、uint16 extra flags、uint32 core clock、四个 float x/y/z/o、uint32 fallTime。GUID=9 时共 32 字节。
- WALKING=0x100，开始 flags=0x101，停止 flags=0x100。
- 使用 Session.GetClock（与 core 时间同步相同原点），不使用 bridge 的独立采集时钟。
- 沿登录朝向计算 XY，速度按本轮基础步行 2.5 码/秒，0.5 码等待 200 ms 后发 STOP。当前不调整 Z。
- 接口 `bridge.step(distance)` 限有限正数且≤1 码；每个登录位置只能消费一次，重复调用需重新入场获得新基线，避免将未经确认的提交位置叠加成可信状态。
- 参数 2 码被拒绝 InvalidArgument；成功一步后重复调用被拒绝 FailedPrecondition。并发动作串行化。
- 正常 START 后 STOP 使用独立 3 秒上下文，避免 HTTP 调用方取消直接跳过停止；写入/连接失败仍可能结果未知，禁止自动重试。

源码依据：本机 `WorldSession::Read/WriteMovementInfo`、`MovementHandler.cpp:344–395,518–605`；服务端验证 mover、坐标、传送/移动限制并处理位置。普通移动广播不保证回送自身，所以本次采用退出重登位置作为确认。

- `scripts/wsl_bridge_probe.py --run-id run03_step --step`：发送一次动作。

- `results/agent_wow_bridge_run04_verify.json/.packets.json/.log`。

run03 的 trace 主要为动作前轮询，动作请求结果另存于结果 JSON；不能当作已记录所有动作后事件。run04 的位置证据直接保存在 login_position。

## 尚未解决

不是 moveTo；没有转向、逐点导航、地面高度/楼层确认、游泳运输/飞行、动态障碍、移动速度更新、强制移动 ACK、跨地图和卡住恢复。需要先实现运动事件及状态失效处理，再扩成长程控制器。附近生物 MONSTER_MOVE 仍未解析。当前每会话一步的限制是实验定位设计，不代表协议只能移动一次。
