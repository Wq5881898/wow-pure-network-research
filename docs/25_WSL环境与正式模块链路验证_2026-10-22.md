# WSL 环境与正式模块链路验证

日期：2026-10-22。已完成用户要求的 WSL Linux 研究环境配置，并验证真实模块往返。

## 环境

- Windows 重启后 VirtualMachinePlatform=Enabled、HypervisorPresent=True。
- 发行版 WoWLab，Ubuntu 24.04.5，WSL2；安装目录 `C:\APP\WSL\WoWLab`。
- Linux 用户 wowlab，加入 docker 组；该发行版启用 systemd，Docker 随其启动。
- Go 1.27.3（下载 SHA-256 校验通过）、Docker Engine 29.1.3、Compose 2.40.3、protoc 3.21.12、Python、CMake、C/C++ 构建工具。
- Linux 原生工作目录 `/home/wowlab/wow-research`，避免将 Unix sockets、数据库和权限测试放到 Windows 挂载目录。

进入环境：`wsl -d WoWLab -u wowlab`。没有改变现有 Windows AzerothCore 配置。

## 验证结果

1. 本地 scratch 镜像构建并成功运行静态 Go 程序，容器退出 0。
2. 固定 core 提交在 Linux 上 `go test -json ./...` 返回 0，`go build` 返回 0；此前 Windows 失败的测试在本轮 Linux 全测试中通过。
3. WSL 经 NAT 网关 `172.22.112.1` 可以访问 Windows 3724/8085；Linux 回环不能直接访问 Windows。
4. 使用临时 WSL 回环 TCP relay 转发 3724/8085 到动态查询的网关，以兼容 realm 返回的 127.0.0.1:8085。relay 随验证脚本退出清理，不改变 realm 数据、宿主防火墙或全局网络模式。
5. Linux Agent WOW 正常 SRP 登录并列出原 Netprobe（GUID 9），未重复注册/创建。
6. 正式 Compose/Unix socket/gRPC 模板入场成功，JSON-RPC `example.query_time` 返回后轮询 `example.status`，观察 packetsReceived 从缺省 0 增为 1，serverTimeUnix=1792616759。
7. `session.logout` 返回 closed，CLI 退出 0，所有模块容器清理；本轮结束 `docker ps -a` 无剩余容器。

## Docker Hub 网络与构建适配

Docker Hub hello-world 拉取连接超时，不将其归因于 Docker daemon 故障；本地容器已验证可运行。

模板原 Dockerfile 依赖 golang:1.27.1 builder 镜像。本轮采用 Linux 宿主 Go 编译原模板服务，再构建 scratch 镜像；模板 go.mod 在 Linux 工作副本 replace 到已固定 core。**服务源码未改，但构建方法与原 Dockerfile 不同**，不能称所有上游部署细节完全原样。Compose runner、UDS、gRPC 健康与业务调用仍经过真实容器链路。

模板原来依赖 core v0.1.0，本轮明确用固定 main 提交；差异记录于结果 JSON。descriptor 使用归档模板已有 module.pb，protoc 已安装但本次没有声称重新生成绑定。
