## 契约与执行器

`scripts/agent_wow_contract.py`：

- `Observation`：后端、角色、会话ID、序号、采样时间、地图、位置、生命/幽灵/战斗、等级、任务日志、物品汇总、可用字段、后端上下文。
- `Action`：动作ID、类型、参数、超时、是否有副作用、前置条件、期望后置条件。
- `Result`：success / failure / timeout / unknown / paused。
- 规则：请求已发出不等于效果成功；后置条件未观察到时，有副作用的动作记为 unknown 而非成功；请求被拒（error）记为 failure；副作用超时记为 unknown；后端明确声明“未产生副作用”时记为 failure。
- 每个动作写一行 JSON 结构化日志，并在动作前后写检查点。检查点同时记录 `completed` 与 `attempted`（已派发的副作用动作），续跑时先读状态：已派发且未确认的动作不重发。

`scripts/agent_wow_session.py`：从探针脚本中抽出共用引导（模块构建、relay、登录），并实现契约后端。`scripts/wsl_bridge_probe.py` 改为调用同一 `ensure_bridge_module`，两条入口走同一条构建路径。

`scripts/wsl_task_runner.py`：一个任务单元 = 核实状态 → 选一个目标 → 接近 → 一次战斗 → 拾取 → 恢复 → 退出。动作失败时在退出前做一次尽力 logout。

离线测试 `scripts/test_agent_wow_contract.py` 8 组：成功路径日志与检查点、前置条件失败、副作用未确认记 unknown、请求被拒记 failure、副作用超时记 unknown、预算耗尽记 paused、续跑跳过已确认动作、续跑拒绝重发未确认副作用。与恢复规划 4 组、世界状态 22 组合计 34 组通过。

## 结论与边界

已证明：一个有界任务单元可以在契约约束下端到端完成并由独立重登核对；失败会被归类并停在该步，不会盲目重试有副作用的动作。
