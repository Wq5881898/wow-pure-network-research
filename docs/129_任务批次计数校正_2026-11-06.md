# 任务批次计数校正

## 先更正待办

实际读取当前 `agent_wow_quest_batch.py` 发现物品分支早已使用item_totals。旧交接及124/125/128所称“仍读任务栏计数，待修”不是当前代码事实，不能据旧报告重写整个分支。

## 本批修正

- item_totals缺失或数量格式异常返回未知，不把缺失报告视为0。已提供字典中缺少物品仍按0处理，前提是报告库存覆盖完整。
- kill计数复用 `agent_wow_objective.progress`，按选定slot解包四个uint16计数，拒绝缺失/重复任务，修复原先忽略kill-slot直接返回第一个uint32。
- quest-id缺省时不向运行器传字符串None；可选目标没有可读新计数时保留内部计数，不让下一单元发生None比较异常。
- 单元数限制1..3，槽位0..3，目标总数及物品entry必须为正。无任务练级不因无关计数终止为objective_reached。

验证：5项离线计数测试通过，覆盖物品不等于击杀计数、缺失库存未知、异常数量、四槽解包、缺失/重复任务。尚未做完整批次模拟入口或实机。

## 下一步业务缺口

1. 无任务/物品任务/可选目标的完整批次入口，需用模拟运行器覆盖参数及停止条件，不只测试计数函数。
2. 当前 `_run` 使用subprocess.run(timeout=900)，可能超时终止正在持有恢复会话的子进程，与持续监督所有权存在冲突。批次不得在该问题修复前开展无人值守实机。
3. `_observe`入口仍属于旧只读登录程序，必须核对其force关闭和退出处理，不能假定“只读”意味着无战斗风险。
4. 最终状态与战斗动作是否真正成功仍需独立验证；计数增加不自动证明整个单元或批次安全收尾。

本轮未启动任务、未登录角色，未提交/推送。

## 子进程预算与只读观察收尾（后续完成）

批次执行与观察不再使用subprocess.run(timeout=...)，改为Popen.wait分窗口等待。超时只写 `agent_wow_owner_wait_<run>.json`（PID、过期窗口数、等待状态），不terminate/kill，不发起第二个登录。输出重定向临时文件以防管道堵塞，仅回传64KiB尾部；临时输出占用磁盘仍可能增长，未实现轮转。诊断写盘OSError不释放执行者所有权。

观察入口移除close(force=True)和直接登出，使用共用持有监督；设置finish_budget_seconds=0禁止收尾恢复主动攻击，允许停手/已有撤离。无路时仍可能只能保留会话并监督，不能保证存活。观察只有获得正常登出收尾才PASS，父批次拒绝非PASS/错误/非零退出，移动或战斗子进程失败也停止继续登录。
