# 练级拾取未知的分项复核

## 四次不能混为同一原因

正式练级c_01的loot有服务端物品7074 push，背包0→1，release RPC返回成功；旧expectation却要求默认任务物品4862增长，因此报unknown。修正一般练级按实际attempted_take_entries、confirmed_item_pushes与对应库存增长验收；有物品任务时仍要求指定任务物品。

c_02/03/04只有首次take发出，无confirmed_item_pushes，库存也未增加，reason为 `take item push not observed; no further requests sent`。其请求后归档无0x160/161/162/166响应，不能因此证明服务端未回复其他错误。桥接当时未订阅SMSG_INVENTORY_CHANGE_FAILURE（0x112），缺少背包变更失败证据。

## 修正与待测

- 新增 `loot_confirmed` 判据，历史归档反例断言01可满足一般拾取，02..04仍不满足；不回写旧任务状态。
- 批次不再仅凭进程exit=0就继续：run.status非success时停止并要求核对，不将unknown动作汇总成batch_complete。
- 桥接新增0x112订阅，worldstate记录首字节InventoryResult与原始载荷，不猜枚举含义。take后发现新失败事件停止，不自动重试。
- 证据限制：release RPC成功仅证明请求层成功，不代表已独立解析释放确认。一般拾取判据至少确认一个实际尝试物品的入包，不保证多物品全部收齐。

验证：历史归档拾取测试2项通过（包含四个子例）；worldstate22项通过。未部署本次桥接订阅或重新实测，0x112专门解码/真实后端失败入口仍应补反例。下一步一次单目标击杀拾取复测，明确记录错误码；若证实库存容量问题，再做出售/补给，不预先删物品或改库。
