## 实验 B：独立 SDK observer 与时间查询

源码：`probes/AgentWowSDK/`。通过 Go replace 使用同一固定源码工作副本，独立实现上游 `modrt.Runtime` 接口，直接利用 Session.SendPacket 与 Publish 回调；**不是 Docker/UDS/gRPC manifest 模块部署**。该实验将业务协议往返与 Linux 部署条件拆开，未改变上游 core。

流程：正常 SRP→realm→角色列表→验证已有 Netprobe→EnterWorld→接收登录位置→发送一次 CMSG_QUERY_TIME→等待匹配 SMSG_QUERY_TIME_RESPONSE→检查长度→正常 Logout。

| 观察 | 单次结果 |
|---|---|
| map | 1 |
| x/y/z/o | -618.5180053710938 / -4251.669921875 / 38.71799850463867 / 0 |
| 查询响应 | 8 字节，两个 little-endian uint32 |
| server_time_unix | 1792561754 |
| daily_reset_seconds | 58246 |
| 请求到回调耗时 | 2.34 ms，本机单次样本 |
| 正常退出 | 成功 |

完整结果及 opcode 计数：`results/agent_wow_sdk_query.json`。位置来自实际 LOGIN_VERIFY_WORLD，不是数据库或本地导航输入。坐标接近前轮离线导航样本，但此轮没有发送移动指令。

SDK observer 目前只解析登录位置/时间响应并按 opcode 计数；其余包保持不透明，不称作完整对象模型。首次入场与等待期间已收到压缩对象更新、普通对象更新、MONSTER_MOVE 等，下一轮可针对这批消息建立有界采集与解码。现有探针不保存原始包体。

## 可复用部分与下一轮

- 确认核心协议与当前本机服务端基本兼容，不必重写 SRP、角色列表或基础会话。
- 账号/角色/配置目录已确定，后续直接复用 Netprobe。
- Linux Docker 模块部署仍未验证；SDK observer 成功不能替代 descriptor、UDS、健康检查和 before_logout 的实测。
- 下一步优先采集初始对象更新，处理 zlib 有界解压、packed GUID、创建/字段增量/销毁，建立带序号和完整性标志的状态模型。
- 短距离移动前需核对 mover GUID、移动 flags、clock、位置与停止/确认语义。尚未验证移动、施法、拾取、任务或战斗闭环。
