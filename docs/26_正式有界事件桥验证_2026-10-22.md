# 正式有界事件桥验证

日期：2026-10-22；复用 WoWLab、AWLAB960D7C、Netprobe GUID 9。

## 本轮成果

新增 `probes/AgentWowBridge/`，将原 SDK 采集能力接入真实 Agent WOW Compose 模块体系：

```text
AzerothCore → 固定 core → gRPC OnPacket → Docker bridge 缓存
→ JSON-RPC bridge.poll → Python 分页归档 → 离线世界状态解析
```

没有发送移动/攻击/聊天；模块只订阅 LOGIN_VERIFY_WORLD、UPDATE_OBJECT、COMPRESSED_UPDATE_OBJECT、DESTROY_OBJECT。行为执行接口尚未暴露。

## 契约与容量

`Poll(after,limit)` 返回 session_id、self_guid、first_sequence、last_sequence、gap、dropped 和 packets。序号只代表订阅子流，不代表所有服务器消息。protobuf uint64 经 JSON 编为字符串，客户端按整数处理；payload 为 Base64。

- 缓存最多 1024 项、4 MiB；超限淘汰最旧记录，累计 dropped。
- 单包上限 1 MiB。
- 默认每页 64，最大 128；每页原始载荷合计最多 1 MiB。
- after 早于保留窗口时 gap=true；after 大于最新序号拒绝。
- OnPacket 仅复制并入队，Poll 返回深拷贝；没有模型或解码工作阻塞 core 收包。
- 时钟为 bridge 服务启动后毫秒，与 core 的游戏时钟不是同一时间原点；当前仅作采集时间戳，不能直接用于发送移动包。

模块 retention/cursor 测试通过：1026 条输入导致保留窗口从 3 开始、dropped=2，缺口正确标记；响应修改不污染缓存；超前 cursor 和过大 limit 拒绝。

## 构建与真实实验

`scripts/wsl_bridge_probe.py` 在 Linux 原生工作目录准备模块，安装固定版本 Go protobuf/gRPC 生成器，实际执行 protoc 生成 descriptor 与 Go 绑定，运行测试、编译静态服务，再用 scratch Dockerfile 构建。

与上一轮模板一样，不依赖 Docker Hub builder 镜像；core 使用本地固定提交 replace。模块由本项目编写，不是声称找到了作者实验完整桥源码。

12 次轮询，每次 limit=4、间隔约 250 ms。累计取得 7 条消息，序号连续：第一页 4 条、第二页 2 条，稍后再取 1 条；后续空页正常。请求未来 cursor `18446744073709551615`、limit=129 均经真实 JSON-RPC/gRPC 返回 InvalidArgument，随后仍可正常退出。

离线重放：7 条消息、57 个对象事件，PASS，无解析错误；自身 level=1、health=70/max=70，位置与登录验证一致。

`session.logout` 返回 closed，CLI exit=0，`docker ps -a` 无残留容器。

## 证据与复现

- 模块源码、proto、manifest、Dockerfile、Compose、测试：`probes/AgentWowBridge/`。
- `results/agent_wow_bridge_run01.json`：分页与错误响应、退出结果。
- `results/agent_wow_bridge_run01.packets.json`：实际消息与 session_id。
- `results/agent_wow_bridge_worldstate_run01.json`：解码快照、事件、采集哈希。
- `results/agent_wow_bridge_run01.log`：core/模块生命周期日志。

复现命令：

```powershell
wsl -d WoWLab -u wowlab --exec python3 "/mnt/c/APP/opencode/project/WoW自动化预研/scripts/wsl_bridge_probe.py"
python scripts/agent_wow_worldstate.py results/agent_wow_bridge_run01.packets.json results/agent_wow_bridge_worldstate_run01.json
```

当前脚本固定 run01 输出，重跑前另存历史样本。实际归档只覆盖退出前轮询窗口，不覆盖退出等待期间的所有消息；capture_complete 表示此选定前缀已连续取回且会话正常完成，不能解释为全会话全量消息。
