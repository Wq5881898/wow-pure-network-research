# 架构收敛与阶段实施计划

## 用户要求与本轮决策

用户明确要求先规划，停止无边界细节实验，减少后续返工；不排斥 Python。当前暂停新增短步、帧数、步行精度实验。语言是实现选择，不是验收目标。

本文件是当前实施计划；不表示规划内容已完成。优先交付本地 AzerothCore 的有界任务执行器，最终 Forever 适配仍需独立能力验证，不能把本地成功直接推广。

## 现状与复用

1. 客户端路线：Python 负责输入和编排，Lua 负责只读状态/逐帧记录。完成短步、模式切换、一次纠偏等，仍依赖 reload 落盘，缺少正式低延迟观测通道。输入精度不稳定，不能继续将5e-06地图容差当作产品要求。
2. 纯网络路线：已有 Agent WOW 桥、导航、状态解码与 Python 编排，完成击杀/拾取/任务788交付；docs/50 的 run96 记录 Netprobe 89/89、蝎尾2/8，增量世界状态已实测。此为历史最近记录，后续开工须新会话核实。长会话、失败战斗退出和危险区跑尸仍有缺口。
3. 两条路线使用不同角色、不同连接和不同数据来源，禁止混用位置、任务进度或状态。危险区跑尸与灵魂医者是不同恢复策略，遵守 AGENTS.md 的验证纪律。

## 架构选择

建议以 Python 承载任务编排、策略、检查点和日志，保留已有协议桥及底层语言实现。Lua 固定为客户端内观测/界面模块，不为统一语言将成熟模块重写。普通插件 Lua 的受保护动作限制不会因为代码迁移而消失。

结构：任务状态机 → 状态/动作契约 → 一个活动后端。

- `Observation`：backend、角色标识、会话ID、序号、采样时间/新鲜度、坐标系与地图、角色/任务状态、字段可用性。
- `Action`：动作ID、前置条件、超时、单步边界、期望后置条件。
- `Result`：成功、失败、超时、结果未知；“已发出请求”不能等于效果成功。
- 后端：优先包装现有纯网络实现；客户端后端保留实验入口，后续再接入正式契约。后端必须声明能力差异，不能假装接口完全等价。
- 任务策略只依赖所需能力；协议解析、Windows输入和Lua接口细节留在后端。

不做通用插件平台或一次重写所有 scripts。先为一个流程提取最小契约，再随真实需求扩展。已有 trace、解析器、导航、输入、Lua探针与状态校验作为可复用资产。

## 实施阶段与验收

### P0：冻结范围与能力清单（下一次开工）

核对纯网络现有入口、测试和最近检查点，列出可调用能力及未实现项。确定首个流程为“启动会话→核实角色状态→选择单个满足条件的目标→接近→一次战斗→拾取→等待恢复/确认状态→保存→退出”。失败分支进入有界恢复或明确暂停，不盲目重试。

交付：入口/依赖清单、状态图、输入输出示例、恢复策略。退出标准：每个状态有进入条件、成功证据、超时与失败出口。不新增游戏动作实验。

### P1：最小任务执行器

用已有实现包装单个可运行入口；任务配置包含backend、角色、目标范围、总时限、动作预算和停止规则。实现状态转换、结构化动作日志、检查点和重启时重新核实。结果未知时先读状态，不自动重发有副作用动作。

验收：历史trace回放覆盖正常完成、死亡、超时、断线/过期状态；能从检查点恢复控制状态，但必须重新建立真实状态。验证过程不依赖重新登录多次证明相同底层事实。

### P2：一个真实流程端到端

在本地已验证区域执行一次有界任务单元。验收以真实目标死亡、物品/任务状态变化、角色最终状态及正常退出为证据。随后最多两次重复用于发现明显不稳定性，不据此宣称统计可靠性。

死亡处理：可行且已验证的恢复路径才自动执行；不满足条件则记录并暂停。危险区域跑尸研究保留专门任务，不借单目标MVP隐式扩大范围。

### P3：有限任务批次

只有P2通过才做最多3个任务单元的批次，验证累计进度、失败预算、日志容量、重启恢复和最终重登状态。再选择一个已有任务收集/交付流程接入，不同时推进多个职业与区域。

### P4：客户端/目标环境适配决策

先验证目标build的数据可读性、执行能力与实时观测出口。若正式目标必须经客户端执行，则将已验证任务契约接入客户端后端；Lua整理为正式观测模块，Python继续作为执行器。SavedVariables只用于归档与排障，不默认作为实时反馈通道。候选屏显编码/截图或其他可用出口必须先做小验证，未验证前不承诺延迟与吞吐。

纯网络若不适用于最终环境，保留为本地参考后端；复用任务状态机/日志/回放而非强迁协议实现。长期要Lua主导策略时，依据明确需求再评估宿主接口，不提前双份实现。

## 实验预算与停止条件

- 每个新增实验必须对应阶段验收的一个具体阻塞项，写清假设、结果如何改变决策。
- 一个问题最多两轮新实验后评审：收敛结论、改变方案或显式列为阻塞，不无期限追加相邻参数。
- 精度由任务要求决定：接近、攻击、交互应按对应范围与可达性判断，不要求返回像素级/极小地图坐标误差。
- 先做回放和已有证据分析；仅缺真实环境证据时才运行新动作。
- 每阶段交付可运行入口、验收结果和未完成边界；不以新增文档数或脚本数衡量进展。
