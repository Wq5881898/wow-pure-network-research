## 解析补齐

离线世界状态解析器现在支持：

- `SMSG_ATTACKSTOP`（0x144）：packed attacker GUID、packed target GUID、target dead uint32。
- `SMSG_ATTACKERSTATEUPDATE`（0x14A）：HitInfo、攻击/目标 GUID、完整伤害、overkill、子伤害学校/浮点/整数、吸收/抵抗、目标状态、blocked、spell ID 等条件字段。

源码依据：AzerothCore `Unit.cpp:6890–6975` 的 `SendAttackStateUpdate`；字段条件由 HitInfo 决定，不能按固定长度切包。

## 真实攻击实验结论

run18 的攻击包计数含 `SMSG_ATTACKSTART` 1、`SMSG_ATTACKSTOP` 1，没有 `SMSG_ATTACKERSTATEUPDATE`。解析后的 `attack_stop` 能读出攻击者 GUID=9，离线重放 PASS；9 组测试全部通过。

因此当前已定位：

```text
请求写入 → AttackStart/AttackStop
          ↛ AttackerStateUpdate / 目标生命下降
```

这不是“解析器漏读”的问题。服务端在攻击状态层处理了请求，但攻击周期没有产出伤害事件。可能条件包括近战距离、朝向、LOS、目标运动时效、攻击间隔/武器条件；当前证据不能单独确定其中哪一项。

run15/run17 的 reason=1 logout 是未显式清理攻击状态；run18/stop_attack 对照证明显式 CMSG_ATTACKSTOP 后可正常退出。攻击失败结论与退出清理结论分开记录。

## 下一步实验边界

不再盲目重复攻击。每次实验必须先保存：自身位置/朝向、目标最后位置、目标 GUID、目标 health、两者距离、目标运动消息的最新时间。攻击后收集 AttackStart/Stop、AttackerStateUpdate、对象 health 增量，最后显式 AttackStop 再退出。
