### 4. 一个必要的代码改动：战斗动作自己拉近距离

huntD 第一次跑时：战斗 `target_left_melee`（目标离距）、HP 全程 108。
原因是 **3101 是游走的远程施法者**：新会话落地后目标已走出近战范围，
而 `fight()` 只在 ≤5 码内交战。

**改动**：`_do_fight` 在交战前先**自己走近**（`_close_distance`）。
这一步不需要确认落点 —— 战斗动作自己的后置条件
（**目标死亡 + 任务计数推进**）就证明了整个过程。
（单独把接近做成计划步骤是走不通的：它的后置条件"确认落点"在本会话内不可观测
（docs/55、docs/88），计划会在那里停住。）

## 失败：huntD 造成角色死亡（第 5 次）

huntD 用改动后的代码跑：**接近成功**（4.84 码，已在近战范围），但：

```
fight outcome = target_left_melee   ← 3101 边打边退，退出了 5 码
fight rows = 79，HP 108 → 93
```

然后计划中断，恢复分支接手，**但没能救回来**：

| 环节 | 实际发生 |
|---|---|
| 恢复分支的结局选择 | `ending = finish_target`（目标已残血、角色尚健康 → 按共享规则选"击杀"） |
| 击杀尝试 | **`fallback_outcome = preconditions_not_met`** —— 目标已退出近战范围，`fight()` 拒绝开战 |
| 退出路径 | `requests = "observation + stop_attack + one retreat"`，但 `combat_cleared = false`，`reason = health floor reached…` |
| 结果 | **角色死亡**（HP 46 → 0） |

**根因**：**恢复分支假设目标够得着。**
共享规则按"目标残血 + 角色健康"选了"击杀"，但目标已经**退出近战**，
`fight()` 的前置条件（距离 ≤5 码）不满足 → 这一步变成空操作。
于是角色站在原地（撤离也没成功），直到被打死。

**这条是本轮新发现的机制缺口**，不是阈值问题：
**目标脱离接触（target_left_melee）之后，"击杀"这个结局不可执行，
必须退化成"撤离"。**

## 结论与下一步

**没有达成 limit-1 击杀**，但三件事是真的：

1. **狩猎链路的移动段已实机跑通**（分段规划 + 新登录观察），刷新区确有 level ≤3 的 3101；
2. **战斗动作自己拉近距离是必需的**（3101 是远程游走目标）；
3. **恢复分支对"目标已脱离接触"没有处理** —— 这是下一次死亡的直接原因。

下一步应当是：

- **让共享规则考虑可达性**：目标不在近战范围时，"击杀"不可执行 → 必须退化为"撤离"；
  并给恢复分支补上"追不上的目标"这一分支（要么走过去再打，要么立刻撤）。
- 修好后重跑 limit-1 单元；**在它通过之前不再跑更多的狩猎单元**。
