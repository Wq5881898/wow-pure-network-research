## 3. 解析依据

本机 AzerothCore 源码，先前记录 HEAD 为 `eb3cdd1d1fbdc98a3a59be80e94b2eb592e1ed04`：

- `Entities/Object/Updates/UpdateData.cpp:48–68`：开头 uint32 block count；没有额外假定的 transport byte。
- `UpdateData.h:26–49`：VALUES=0、MOVEMENT=1、CREATE=2/3、OUT_OF_RANGE=4、NEAR=5，以及 16 位 update flags。
- `Entities/Object/Object.cpp:332–510`：movement 条件字段、9 个速度、字段掩码和增量值。
- `Entities/Unit/Unit.cpp:15867–15917`：movement flags/flags2、时钟、坐标朝向、transport/pitch/fall/spline elevation。
- `Movement/Spline/MovementPacketBuilder.cpp:159–200`：create spline 的朝向分支、时间/持续、节点与终点。
- `Entities/Object/Updates/UpdateFields.h`：字段索引，OBJECT_END=6；health=0x18、maxhealth=0x20、level=0x36。

对象 GUID 以字符串存储，避免 64 位值经过 JSON/JavaScript 浮点后失真。字段值保留原始 uint32；不同对象类型必须采用各自字段定义，不能把 item/gameobject 的同索引当作生命值。

## 4. 有界采集和完整性语义

- SDK 回调只复制选定消息并编码，暂存上限 4096 条、原始载荷合计 8 MiB；超出上限返回错误，不静默覆盖。
- 本轮序号专用于选定消息子流，不是完整 socket 流序号；未选择的 opcode 不算缺口。
- session_id 为会话启动 UTC 时间；每条记录有启动后的单调毫秒数。只在正常实验结束并生成文件后标注 capture_complete。
- 不采集认证数据、Warden 包体或聊天；对象载荷可包含游戏角色/资产状态。
- 单条解压上限 8 MiB，验证声明长度、zlib EOF、unconsumed tail 与 unused data；拒绝超长和拼接/尾随压缩流。
- 离线文件输入上限 16 MiB，包数、block count、GUID count 和 spline 节点有界。
- 每包先完成解码再应用；应用异常会回滚该包的对象变更，整次 replay 标为 INCOMPLETE，不能将后续快照当作可信完整状态。
- delta 没有先前 create 时拒绝，序号缺口拒绝；保留错误位置，不自行猜测字段边界。

当前采集器是短实验的内存缓冲，不是持久事件服务；异常退出可能没有 trace，不提供断线重建。Base64 与 JSON 会增大体积，不能把原始 8 MiB 当作磁盘文件大小。

原始字段掩码只发送非零和可见字段，未传输字段可能是零、不可见或不适用；摘要为了展示使用零默认值，但原始 `fields` 保留哪些索引实际出现。**零默认值不能证明可读性**。战士 power type 可从 bytes0 解码，不能把 powers[0] 直接叫作战士资源；后续应提供类型化表示。

## 6. 验证与尚未覆盖分支

5 组测试通过：真实样本确定性重放、自身位置/等级/生命与附近生物检查；所有真实对象更新包的截断前缀拒绝；超限/长度不符/尾随压缩数据拒绝；序号缺口及损坏 Base64 标记不完整；packed GUID 与未知 update type 检查。

真实样本覆盖 create、values、out-of-range/destroy；MOVEMENT type=1、NEAR type=5、载具、运输、游泳/飞行、复杂 spline 分支未逐项由实测覆盖。实现解析分支不等于证明这些场景都兼容。

最重要的限制：**未采集/应用 MONSTER_MOVE 等运动事件，附近生物位置会过时**。此处“可见对象”仅指最后一次生命周期状态缓存，不是服务端全地图，也不能直接用于追逐或战斗。物体名称、敌友关系、可交互性、死亡/施法状态还需类型化解码和额外消息。
