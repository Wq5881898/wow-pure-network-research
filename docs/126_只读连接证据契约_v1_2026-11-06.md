# 只读连接证据契约 v1

## 已实现：观测证据，不是健康证明

`Observation.context.connection_evidence`：

| 字段 | 语义 |
|---|---|
| schema_version | 1 |
| session_id | 与抓包同一会话，变化拒绝混用 |
| last_received_packet | 最新接收包的sequence与会话monotonic_ms |
| last_received_pong | 最近0x1DD包的sequence、packet_ms、ping_id；只有4字节载荷才接受 |
| valid_pong | null：匹配与有效期结果未暴露 |
| world_connected | null：不由本层宣称连接正常 |

空轮询不刷新收到时间，任意其他包不刷新Pong。字段读取不发送网络探测、不触发游戏动作、不改变既有RPC或proto。

## 为何不能把收到Pong当有效Pong

本机Agent-WOW `pkg/world/protocol.go:32–49` 只有在pending pings里存在同ID、且尚未过期时才续期看门狗；未知ID或过期Pong也可能被发布给模块。因此桥接所见原始Pong不携带有效性结论。当前实现明确保持null，禁止据最近原始Pong解除恢复锁存或授权登出。

## 下一版接口候选，尚未实施

若需要有效心跳证据，应由底层单所有者engine在完成匹配后维护只读snapshot：session状态、最近有效Pong的本地单调时间、采样时间、有效期、失败原因、会话身份。通过有版本的只读接口暴露；不得让桥接自行重复推断，也不得让健康查询发送Ping或重置watchdog。

该变化涉及外部Agent-WOW工程的Session/proto或RPC契约，本批没有改动上游接口。需先核对其维护约定和契约变更范围，再实施并测试未知ID、过期Pong、断线、RPC采样竞争与版本缺失的降级处理。原始Pong记录只是前置观测能力，不能替代该接口验收。
