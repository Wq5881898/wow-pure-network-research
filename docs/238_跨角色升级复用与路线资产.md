# 跨角色升级复用

目标：同版本、同种族职业的下一个号，读取角色状态后用固定入口执行已验路线；正常流程无需 AI 重新研究、生成脚本或逐段接续。

## 原项目与当前差距

- 上游 `agent-wow`：登录会话与模块 RPC 是固定接口；workspace 按模块、脚本、日志和经验笔记组织。官方 main 没有可直接复跑的 1–60 路线。历史可审阅的 PR18 提供路线、职业、任务与库存运行模块的结构示例，未合并。来源及边界见 `docs/195_上游复现优先与十至二十级路线准备_2026-11-12.md`。
- 原客户端工程：固定手册入口、离线检查和标准验收链。这种交付方式可借用，窗口驱动本身保持独立。
- 当前纯网络工程：`agent_wow_batch.py`、`wsl_task_runner.py`、`efficiency_session.py` 已有批次、战斗和巡逻能力；但角色仍存在 `char play 9` 等硬编码，路线配置及状态转移散落在单次 `.cache` worker，部分路线还依赖本地结果。跑到某级不证明另一角色能用同一入口重跑。

## 固定交付结构

| 层 | 应持久化的内容 |
|---|---|
| 会话与动作 | 角色与登录配置参数化；固定登录、迁移、巡逻、战斗、恢复、修理和退出接口 |
| 职业策略 | 以版本与职业为键的数据配置，含技能可用条件、食物、训练及装备策略 |
| 分段路线 | 起止等级、地图与区域、目标规则、入场/巡逻/退出/跑尸路径、任务与必需整备 |
| 进度与证据 | 每个角色独立进度；从实时等级、位置和已完成任务恢复；路线版本绑定历史验收 |

剧情与机制尚不明时由 AI 离线研究和形成新版本；可重复场景由程序执行。未知状态保留明确阻塞原因，并回放形成回归，避免每个号再踩一次。

## 第一份可用索引

```powershell
python -X utf8 scripts/leveling_catalog.py 12
python -X utf8 scripts/leveling_catalog.py 18
```

`data/leveling_stages.json` 覆盖查询区间 1–60。`historical` 表示有历史结果可提取，`trial` 表示试验线索，`unmapped` 表示尚未编入路线。输出会标出本地证据缺失；本地缓存引用不能作为已发布路线包的运行依赖。该入口仅查询，不启动游戏。

## 18→19 东部猎区检查点

`scripts/leveling_rectangle.py` 与 `data/rectangle_barrens_east_18*.json` 保存了本机入口和路线候选。入口目前仍依赖本机 WoWLab 配置及 `.cache` 中的 worker 和导航准备模块；这次归档不是全新检出即可运行的发布包。

用户交接点为 `(1116.58, -3405.10, 91.9867)`。每个获桥接接受的短移动块后复扫、30 码内锁定和续走剩余巡逻段已有实机证据。最近西侧 r11 没有开攻：复放中有距离合格的 16 级陆行鸟，但拟定撤离路线进入另外两只迅猛龙的风险范围。需要新的本地起点或独立退路证据才能重测。角色最后核验为 18 级 228/17800 XP、418 满血、正常离线；19 级未完成。

## 正式复跑验收

先从已有数据化巡逻的12→13提取一段：固化全部路线依赖，合并旧 worker 中已经验证的状态转移；把角色标识贯穿登录、协议解析和验收。用另一同类角色覆盖正常巡逻、击杀恢复、停机续跑和到级退出，不允许执行中生成新的专用 worker。通过后才把该路线发布为可复跑，再逐段补回起步及18级以后的资料。每个版本记录完整墙钟、收益、失败分支和兼容范围。
