# 大阶段执行与统一验收计划

## 用户明确的执行方式

先划分大阶段，每阶段包含一组小任务。阶段内条件满足则连续执行，不再每做一个小任务就停止等待“继续”。统一在阶段结束时整理记录和汇报。原始日志、检查点仍在执行期间持续保存，不能等结束才留证据。

遇到问题先定位并修复可独立处理的实现问题，验证后继续阶段剩余任务。目标、范围、恢复代价或技术路线需要用户选择时再提问。失败不得以换run ID反复重试掩盖；不因一个小任务失败立即放弃整个阶段，也不把未知副作用自动重发。

## 阶段一：完成当前收集任务全流程

小任务：
1. 核实角色、任务日志、物品数量和当前会话身份。
2. 选择新目标并复核等级、生命、可见性与距离。
3. 必要时沿导航路径接近，在安全任务边界确认位置。
4. 完成战斗、拾取、脱战；按实际掉落决定是否还需要目标，不预设必掉任务物品。
5. 达到8件后停止额外收集，规划返回任务NPC的可达路线。
6. 核对交互与奖励选项，完成789交付；若存在没有既定规则的有意义奖励选择，再询问用户。
7. 核对物品扣除、奖励、任务日志和最终角色状态；独立重登确认持久化。

验收：不是仅达到8/8，而是789已交付且最终状态已确认；否则归档具体未完成项与原因。阶段内不扩展新任务或区域。

## 阶段二：收敛为可恢复的有限任务批次

小任务：
1. 统一移动、核对、战斗、拾取、交付的任务状态及证据来源。
2. 完善动作/阶段时限、失败预算、超时后的状态核实与退出处理。
3. 加入边界报告的身份、时效、消费标记，避免旧边界误用于新任务。
4. 验证正常完成、死亡、断线、旧状态、未知副作用、日志/检查点损坏等关键分支。
5. 先离线回放，再执行最多3个任务单元的受限真实批次；核对累计进度和重启状态。

验收：单入口可运行、结果可追溯、恢复前重新核实真实状态、未知副作用不盲目重发。不能只凭一次成功宣布稳定。

## 阶段三：危险区域跑尸恢复专项

小任务：
1. 查询最新尸体/墓地，在幽灵状态规划Detour可达回收点及撤离路点。
2. 核对复活条件和可用状态证据，复活确认后立即沿预规划路线向墓地方向跑。
3. 持续监督生命/战斗；再次死亡时查询新尸体，比较到墓地的可行路径距离。
4. 验证阻挡、路线不可达、尸体变化、路径距离未缩短等分支。
5. 以最终持续存活/重登为准，记录复活次数、推进距离和实际代价。

验收：完整记录危险区回收及撤离效果；灵魂医者单独记录，不能代替该专项。前阶段自然触发死亡时先处理恢复，但不把未经验证的恢复函数直接当作可靠自动策略。没有死亡样本时明确未覆盖，不为填表擅自制造死亡。

## 阶段四：目标环境适配决策

小任务：核实目标build与连接能力、实时观测出口、动作能力和延迟；明确纯网络与客户端后端差异；依据证据选定后端并迁移已验证任务契约。具体账号/环境切换或路线取舍需用户决策时提问。

验收：本地AzerothCore结果与最终环境结果分开，不将本地通过推广为Forever已验证。

## 阶段汇报格式

统一列出：小任务通过/失败/未覆盖、关键证据、当前角色和任务状态、已修复问题、剩余阻塞、下一阶段入口。中途只在重要发现、真实阻塞或需要决策时简短更新；不输出反复推演和逐工具操作叙述。
