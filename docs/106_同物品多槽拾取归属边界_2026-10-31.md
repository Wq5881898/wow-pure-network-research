# 同物品多槽拾取归属边界

## 问题

即使第一项`take_loot`已收到0x166回执，若同一loot窗口还有另一个**相同entry**的槽位，0x166只含玩家、物品entry、增加数量和背包总数，不包含源loot slot。第一项迟到或重复出现的回执不能凭entry直接归属第二次请求；仅有第二次请求游标与库存数仍不足以排除所有重复/独立来源情况。

## 本轮处理

后端在第二个同entry槽位发请求前停止，保留第一项已确认的item-push证据，`reason='another loot slot has the same entry; slot attribution unavailable'`，不发送第二次take、不释放loot、不把整次loot记为成功。原先首项无回执就停的规则不变。

新增合成“两槽同entry，首项已有回执”测试，确认take只发一次且不会release；WSL相关8项、全量153项通过。本轮无新游戏动作，不能宣告多槽拾取实机已完成。要覆盖此类情况需额外的源slot关联或经独立重登核对后以新会话/新操作边界继续，不能为消除UNKNOWN而盲重发。
