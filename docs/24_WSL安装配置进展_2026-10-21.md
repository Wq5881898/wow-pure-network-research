## 已执行与真实阻塞

用户要求安装 WSL 并完成 Agent WOW Linux 环境配置。检查发现：WSL 2.3.26.0 已装，但 VirtualMachinePlatform=Disabled，HypervisorPresent=False；已有 docker-desktop 发行版也无法启动，报 HCS_E_SERVICE_NOT_AVAILABLE。

已执行 `Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform -All -NoRestart`。返回 RestartNeeded=True，当前状态 EnablePending。**必须重启 Windows 才能继续启动 WSL2**；本轮没有自动重启，避免中断用户远程会话和现有运行程序。

`wsl --install -d Ubuntu --web-download --no-launch` 在下载微软 GitHub 分发列表时超时。已改用微软公开分发列表中的 Canonical 官方镜像直接下载，并核对 SHA-256：

- Ubuntu 24.04.5 amd64 WSL，388,975,696 字节。
- SHA-256：`bb415d824822c4b878125729af451a5d18fb13d1cf5cbed9a7393ad64ac6039e`。
- 原地址与哈希来源：`results/wsl_ubuntu_image.json`。
- 本地镜像：`.cache/wsl/ubuntu-24.04.5-wsl-amd64.wsl`。

准备目录 `C:\APP\WSL`，尝试导入名为 WoWLab 的 WSL2 发行版，仍因 HCS_E_SERVICE_NOT_AVAILABLE 失败。**下载成功不等于发行版已安装**；尚未运行 Linux/Docker/protoc 或验证 Linux→Windows 网络。

## 重启后的继续命令

以同一 Windows 用户运行：

```powershell
wsl --list --verbose
wsl --import WoWLab "C:\APP\WSL\WoWLab" "C:\APP\opencode\project\WoW自动化预研\.cache\wsl\ubuntu-24.04.5-wsl-amd64.wsl" --version 2
wsl -d WoWLab -u root --exec uname -a
wsl -d WoWLab -u root -- bash "/mnt/c/APP/opencode/project/WoW自动化预研/scripts/wsl_lab_setup.sh"
```

如果 WoWLab 已列出，先检查能否启动，不重复 import。不要 unregister 已有发行版或覆盖其文件。

`scripts/wsl_lab_setup.sh` 为待执行脚本，安装 Ubuntu 包源的 Docker Engine/Compose v2、protoc、Python、构建工具及经哈希核对的 Go 1.27.3，创建 wowlab 用户，并仅在该发行版启用 systemd。如首次修改 wsl.conf 后尚未以 systemd 启动，需要单独 terminate/relaunch WoWLab。脚本未执行，不记为配置成功。

随后还需验证：apt 网络、Docker daemon/Compose/镜像拉取、固定上游 Linux 测试和构建、Windows auth 3724/world 8085 的连通、realm 返回地址在 Linux 中的可达性。默认 NAT 下不能把 Linux 的回环误当成 Windows；先检查实际网络模式，再决定地址转发/镜像网络方案。不改服务端 realm 表以掩盖客户端连接问题。
