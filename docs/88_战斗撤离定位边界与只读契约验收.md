# 战斗撤离定位边界与只读契约验收

## 结论

已验证的逆向步行路线仍只能说明**非战斗路径可行**。当前 `PureNetworkBackend.observe()` 的自身位置来自最后服务器对象 movement，而本机服务端不向当前玩家广播自身移动；登录以后 `position_evidence.current_position_confirmed=False`。战斗中将缓存登录位置或桥接器 `submittedPosition` 当作当前位置，会错误授权下一段撤离。故本轮未开放真实战斗撤离、没有执行游戏动作。

## 本轮代码核验

- `probes/AgentWowBridge/actions.go`：`FollowPath` 返回的 `SubmittedPosition` 是模块自身构造的发送终点，不是独立服务器到位回执；bridge `positioned` 仅表示模块可再次接受路径，不等于角色实际到位。
- `agent_wow_retreat.execute()`：限定一个<=20.1码的路段；要求已确认的同会话自身 movement 序号严格晚于登录序号、来源明确；拒绝陈旧登录证据。请求前独占日志，超时/拒绝回复均保留未知，不重发也不自动 logout。
- 每个路径点按桥接器水平15码、高差3码约束预检；六段历史路径 `prepare()` 离线验证通过，但禁止把六段一次性交给 execute。
- Windows 全量110项通过、1项因仅WSL有`ip route`而跳过；WSL全量110项通过，无跳过。真实后端形状的离线契约测试证实即使合成处于战斗，也不会发出撤离RPC。

## 仍待解决

现有后端无法产生上述战斗中位置证据；此接口目前必然拒绝真实撤离。测试里的“已确认位置”是合成Mock，不是游戏能力。后续需设计和验证战斗中可信位置反馈，或者另经审查的整段单调用路径与受伤状态反馈协议。不能靠放宽布尔条件或多次发送提交终点实现。

此次没有新增真实打怪，亦不把脱战观察与进程退出等同于撤离成功。安全恢复分支仍未验收。
