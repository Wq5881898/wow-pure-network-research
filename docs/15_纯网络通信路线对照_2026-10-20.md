## 2. 首先区分三种网络方案

| 形态 | 实际工作位置 | 是否是独立协议客户端 |
|---|---|---|
| 独立协议客户端/headless client | 自行连接 auth/world，维护会话和角色状态，发送游戏协议消息 | 是，本文主要分析对象；是否匹配原报告待核实 |
| 服务端 bot/模块 | 在 AzerothCore 进程内调用游戏对象和 AI | 否；即使有网络管理界面，也不能当作协议客户端成功证据 |
| SOAP/自建 HTTP/RPC 控制层 | 经管理接口或定制模块下发命令 | 否；可用于实验控制和观测，但依赖管理权限或服务端改造 |

“纯网络”不能只由程序没有截图来定义，必须记录它究竟走普通游戏连接还是管理通道。现有 `lab_soap.py` 是管理接口工具，不是 headless 游戏客户端。

## 3. 与现有路线逐段对照

| 维度 | addon + 外部输入（已有实验） | 视觉 + 外部输入（并列候选） | 独立协议客户端（新增并列候选） |
|---|---|---|---|
| 观察 | addon API、事件 | 画面识别 | 服务器下发消息、对象增量和本地缓存 |
| 出口 | SavedVariables、屏显等 | 截图进入外部程序 | socket 解帧后进入状态存储，无 addon 文件出口 |
| 决策 | 可共用本地状态机 | 可共用本地状态机 | 可共用策略逻辑，需协议状态适配器 |
| 执行 | Windows 输入，游戏客户端解释 | Windows 输入，游戏客户端解释 | 编码游戏消息，由服务端校验和执行 |
| 运行依赖 | 客户端、显示会话、API 版本 | 客户端、显示会话、分辨率/识别条件 | auth/world 会话、版本化协议、数据文件/导航支持 |
| 主要工程难点 | API 可读性、出口时效、焦点与输入效果 | 目标识别、遮挡、识别误差、输入效果 | 认证、分帧、包头加密、状态同步、动作时序、重连 |
| 当前证据 | 3.3.5a 登录和探针落盘：见 docs/12 | 尚无完整视觉行为闭环结果 | 本次收到并解析世界服初始挑战，尚未认证 |
| Forever 外推 | 旧客户端观测不能证明现代 API 语义 | 需现代客户端单独验证 | 3.3.5 协议不能当作现代协议实现 |

优势假设：协议输入输出可能减少显示、识别、焦点问题，并使事件记录更直接；仍需测量端到端延迟、资源占用和重连可靠性，不能直接写“更快/更稳定”。

代价假设：原游戏客户端隐含承担的状态缓存、消息响应、移动时序和数据解释，需要在新客户端实现。网络接收不是完整世界感知：客户端只能维护服务器实际向该连接发送的可见对象，不能据此认为拥有全地图对象或服务端内部状态。

| 主题 | 源码相对路径与位置 | 能支持的结论 |
|---|---|---|
| 登录流程 | `src/server/apps/authserver/Server/AuthSession.cpp:37–131` | 存在 challenge/proof、reconnect、realm list 消息及状态限制，不能只发一条 world 指令完成登录 |
| 初始世界挑战 | `src/server/game/Server/WorldSocket.cpp:223–231` | `SMSG_AUTH_CHALLENGE` 载荷为 4 字节标记、认证随机种子及 32 字节随机数据，共 40 字节 |
| 流式分帧 | 同文件 `242–330` | 服务器显式处理不完整包头与包体；socket recv 一次不等于一个包 |
| 世界认证 | 同文件 `530–624` | 解析 build、账号、realm、挑战及摘要，使用会话密钥验证，不是固定封包重放 |
| 包头加密 | `src/common/Cryptography/Authentication/AuthCrypt.cpp:22–47`；`WorldSocket.cpp:306–313` | 会话密钥派生方向相关的流密钥，ARC4-drop1024；接收端对包头解密，不能笼统说所有载荷都加密 |
| 会话及校验 | `WorldSocket.cpp:594–718` | realm、账号限制、摘要及配置相关的 Warden 初始化等均属于会话条件 |
| 消息标识 | `src/server/game/Server/Protocol/Opcodes.h` | 定义角色枚举、入场、对象更新、移动、施法等标识；标识存在不等于客户端已实现语义 |
| 对象字段 | `src/server/game/Entities/Object/Updates/UpdateFields.h` | 可作为版本化字段解析依据；仍需处理字段掩码、对象生命周期和动态增量 |

动作结果应进一步对照 `src/server/game/Handlers/` 中的 Character、Movement、Spell、Combat、Loot 等 handler。服务端可读源码使实验更容易定位错误，但直接读数据库/调用管理命令得到的能力必须与普通协议连接能力区分。

## 5. 本次运行时测试 N0

工具：`scripts/network_world_challenge_probe.py`。输出：`results/network_world_challenge_2026-10-20.json`。

复现：

```powershell
python scripts/network_world_challenge_probe.py --output results/network_world_challenge_2026-10-20.json
```

脚本只连接固定回环地址 `127.0.0.1:8085`，接收首帧后关闭。应用层发送字节数为 0；未提供账号、未认证、未进入世界。使用精确长度读取，设置 5 秒 socket 超时，校验首帧长度范围和普通包头。初始挑战不应使用扩展包头；遇到该情况会报告异常，不冒充通用协议解析器。
